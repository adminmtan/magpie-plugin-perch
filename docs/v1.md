# 第一版范围与验收

## 目标与事实边界

将客户端的 OpenAI 文本对话请求，经 Perch 适配器转换为上游请求，再输出 OpenAI JSON 或 SSE。Magpie 负责认证、计费、路由、账号持久化与并发管理。

来源：用户提供的 `magpie_custom_perch_ai_plugin_guide.md`。其中网页协议是示例，宿主接口与实际版本不符。现以 Magpie v0.1.3337 源码及 Perch 公开前端为依据实现 `magpie.ts` / `perch-web.ts`，已移除被替代的示例适配代码。当前已完成本机模拟验收，以及正式代码在登录浏览器中的真实 JSON/SSE 转换、续聊、会话隔离和取消请求；插件在浏览器外的 Cookie 鉴权和 NAS 端到端仍未验收。证据见 [integration.md](integration.md)。

## 必须完成的功能

| 功能 | 验收标准 |
| --- | --- |
| OpenCode 默认工厂提供 config/chat.headers/auth.loader/fetch | v0.1.3337 原版 host.js 能加载、注册 perch-ai/perch-default，把宿主 session 传入自定义 fetch，并调用返回 Response 的自定义 fetch；本机首轮与同 session 续聊已通过 |
| 首次与续聊 | 单条 user 创建 thread，发送 message；完整历史精确匹配成功会话才复用 thread。未知历史 409；system、多模态、工具、temperature 等参数 400，不静默修改输入 |
| 凭据与出口 | Cookie 从宿主读取；不转发客户端 Authorization；沿用 Magpie 账号代理作用域；不跟随重定向。本机验证 Cookie 隔离，NAS 代理仍需联调 |
| 非流式对话 | 聚合 answer_delta，仅在 done.ok 为 true 时返回 chat.completion；无真实用量则省略 usage |
| 流式对话 | answer_delta 转 OpenAI 增量，忽略推理与引用；UTF-8/CRLF/LF/尾帧正确；id/created 稳定；成功才输出 stop/[DONE]。失败 done、提前 EOF、正文修订不伪装成功 |
| 失败与清理 | 401 标记登录失效，403 独立为权限错误，429 返回安全的 Retry-After；网络失败、错误内容类型、坏 JSON、上游错误事件均明确失败；不回显上游原文或凭据；全请求超时、调用方取消和下游取消释放上游 |
| 本地完整链路 | 客户端 → 正式 hooks → 模拟 Perch thread/chat → OpenAI JSON/SSE；普通、流式和续聊通过；npm start 可启动 |

## 技术选择与默认值

- Bun + 严格 TypeScript + 原生 Fetch/Streams，无业务框架和运行时第三方依赖。项目 Bun 1.4.4，目标宿主默认 1.4.2，版本差异仍待 NAS 验证。Node 加代理依赖会偏离宿主；浏览器会话方案留待真实需求证据。
- `magpie.ts` 只处理宿主契约；`perch-web.ts` 封装鉴权注入、thread 连续性与真实网页协议；`protocol.ts` 处理有界 JSON/SSE；`demo.ts` 提供本机验证。没有数据库、额外服务或通用 Provider 框架。
- 正式上游固定为 https://chat.perchai.app/，不允许客户端指定。默认关闭，显式开启插件选项 experimental-web 才允许真实请求；fixtureBaseUrl 仅允许本机 HTTP。
- 首次发送单条 user；续聊携带此前完整的 user/assistant 消息。比较方案后选择沿已知 thread 续聊：逐轮重放会产生额外生成与费用；扁平化全文会改变角色语义。因此两者均不采用。未知历史直接 409。
- 会话缓存仅保存历史哈希和 threadId，按 Cookie 哈希与宿主 session 隔离；`chat.headers` 把 Magpie/OpenCode sessionID 写入内部 `x-magpie-session`，直接调用仍兼容该头。最多 128 条，成功后 30 分钟有效，重启、凭据变化或被淘汰后失效。每次续聊消耗旧映射，失败不允许自动重放；上游会话不自动删除。多账号路由须保持同一账号，否则可能 409。无 session 时使用空会话标识，应避免同账号相同历史的并行分支。
- 使用前端默认值：webSearch=false、roostChoice=standard、manualModelOptionId=null、promoOverflowAccepted=false。不猜测底层模型、不自动同意额外额度。此类确认返回 402，去网页处理。
- 仅接收 model/messages/stream；user/assistant 交替，最后为非空 user，最多 256 条。请求与累计回复最多 1,048,576 字符，SSE 单事件/会话创建 JSON 最多 1 MiB。忽略 status/reasoning_delta/citations，未知或 artifact 事件明确报错。
- 默认总超时 60 秒（含流读取），可配置 requestTimeoutMs 为 1–300000 毫秒；每账号单生成，额外请求 429 并给出 1 秒 Retry-After，无排队与自动重试。上游 429 只转发数字或七日内 HTTP 日期格式的 Retry-After。确认的 401 返回 `X-Magpie-Sign-In: expired`，403 不误报登录过期。取消或超时尽力调用 chat/stop，清理额外最多等待 3 秒；网络中断下不保证服务端停止。
- 只声明 `perch-default`、文本能力；不虚构上下文上限、输出上限或 token 统计。
- 流已开始后的错误通过流失败传播；实际 NAS 如何向客户端呈现仍需联调。本地演示输出安全 SSE error 并终止，不追加 [DONE]。

## 暂不包含

自动登录、凭据刷新、验证码处理、浏览器会话维持、图片/附件、system、工具调用、推理字段、多模型发现、历史导入/编辑/分支、持久化会话、数据库、后台 UI、计费、回答缓存、自动重试、分布式队列与通用适配框架。

## 真实验收前必须补充

1. 已确认 Magpie 仓库 `yetone/magpie` 与目标版本 v0.1.3337，已核对宿主 hooks 并通过原版 host.js 的本机测试；NAS 本身仍未联调。
2. 已实现公开前端可见的网页协议，但尚未验证真实 Cookie 是否足够、是否需要 CSRF/刷新及账号权限。需要在本人账号授权环境测试创建会话、首轮、续聊、SSE、过期凭据与取消；凭据只在 Magpie 设置中填写。

真实验收：在指定 Magpie 版本中加载插件、配置本人账号、刷新模型，并通过其 API Key 对 `/v1/chat/completions` 分别完成普通与流式对话，再验证过期凭据和客户端取消。没有这些证据时，状态始终为“本地协议原型已验收，真实接入未验收”。
